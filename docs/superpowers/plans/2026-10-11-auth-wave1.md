# Auth Wave 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Wave 1 auth (sign in, sign up, reset, OTP, magic link, MFA plus recovery codes) as primitives plus recipe demos.

**Architecture:** New presentational React primitives under `src/primitives/Auth*/` following the `AvatarGroup` pattern (component file, `manifest.json`, `README.md`, styles in `design/styles/primitives/`, wired exports via `node scripts/wire-primitives.mjs`). Recipe demos in one new block file `atoms/web/blocks/558-auth-wave1.js` reuse the existing `Track`/`Swap` spring helpers and extend the `otp`, `password`, and `authshell` recipes without replacing them.

**Tech Stack:** React TSX, existing Cieo tokens, vanilla JS recipe blocks, Playwright sync API, axe-core 4.13.0 at `/tmp/lanes/a11y/node_modules/axe-core/axe.min.js`.

**Spec:** `docs/superpowers/specs/2026-10-11-auth-wave1-design.md`

## Global Constraints

- Flat design: inputs use `1.5px solid var(--muted)` edges, never hairline borders.
- Text contrast 4.5:1 or better; control edges 3:1 or better (WCAG 1.4.11).
- Focus visible: 2px accent outline with 2px offset on every interactive element.
- Touch targets 44px minimum on phone and coarse pointers.
- Every control has an accessible name; errors use text, never colour alone.
- No auth secrets in logs, screenshots of typed secrets, or commits.
- Manifest `$schema` is `../../../schemas/component.schema.json` relative to `src/primitives/<Name>/` (the schema file lives at the repo location that path resolves to).

## Review Focus

- Pasted OTP with spaces or dashes still fills the boxes in order; stray characters are ignored, never crash the demo.
- Browser autofill and password managers fill email and password fields; the show/hide toggle keeps focus on the input.
- Rapid resend clicks never start two countdowns; the button disables while a countdown runs.
- Recovery codes typed with spaces or dashes normalize before comparison.
- Dark theme keeps 4.5:1 text and 3:1 edges on every new atom (tokens differ per theme).

- [ ] **Step 2: Create the component**

```tsx
'use client';
import type { CSSProperties } from 'react';

export interface AuthEmailFieldProps {
  id: string;
  label?: string;
  value?: string;
  defaultValue?: string;
  error?: string;
  disabled?: boolean;
  style?: CSSProperties;
  onChange?: (value: string) => void;
  onBlur?: () => void;
}

export function AuthEmailField({ id, label = 'Email', value, defaultValue, error, disabled, style, onChange, onBlur }: AuthEmailFieldProps) {
  const describedBy = error ? `${id}-error` : undefined;
  return (
    <span className="cieo cieo-auth-email-field" data-invalid={error ? 'true' : undefined} style={style}>
      <label className="cieo-auth-label" htmlFor={id}>{label}</label>
      <input
        id={id}
        className="cieo-auth-input"
        type="email"
        autoComplete="email"
        inputMode="email"
        value={value}
        defaultValue={defaultValue}
        disabled={disabled}
        aria-invalid={error ? 'true' : undefined}
        aria-describedby={describedBy}
        onChange={e => onChange?.(e.target.value)}
        onBlur={onBlur}
      />
      {error ? <span id={`${id}-error`} className="cieo-auth-error" role="alert">{error}</span> : null}
    </span>
  );
}
```
