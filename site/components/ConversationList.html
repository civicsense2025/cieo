ConversationList

The inbox: rows with one tab stop, arrow-key movement, and rows that glide to their new places when the order changes.

Usage

Use the import, not the markup. Copy this line into your code; never paste the preview HTML below.

import { conversationIds, conversationOrder, conversationTabbable, conversationRove, ConversationList, ConversationListContext } from 'cieo/ConversationList';
<ConversationList label="Conversations" order={ids} selectedId={openId}>
  {rows.map((c) => <ConversationListItem key={c.id} {...c} />)}
</ConversationList>

Properties

NameTypeDefaultDescription
labelstring—Accessible name for the list.
orderstring[]—Conversation ids in display order; rows glide when it changes.
selectedIdstring—Id of the open conversation.
classNamestring—See TypeScript declaration for the named presentation or content slot contract.
slotPropsobject—See TypeScript declaration for the named presentation or content slot contract.

Guide

Use when

  • Showing a user's conversations, newest activity first.

Avoid when

  • Static, never-reordered menus.

Anatomy

A role="list" div that renders its rows in the order given by order, then any rows not named, in written order.

Behavior

  • conversationIds reads the row ids from children; conversationOrder(ids, order) merges them (unknown ids dropped).
  • When the order changes, rows glide to their new places (shared FLIP). Reduced motion skips it.
  • Focus stays on the same conversation when it moves.

Keyboard / accessibility

ArrowUp and ArrowDown move focus between rows, Home and End jump to the ends, and movement stops at the ends. One tab stop: the last focused row, else the selected one, else the first (conversationTabbable). The list has an accessible name from label.

Do / don't

  • Do: change order when a message arrives.
  • Don't: re-key rows to reorder them.

Customization

Rows are spaced by a space token; style rows through ConversationListItem.

Limitations

  • No virtualization; very long inboxes need the host to window the rows.

Related

ConversationListItem, SortableList.

Host customization

className adds a class to the root without replacing the Cieo class. slotProps accepts named presentation parts: root. Each part accepts className, style, title, and nonreserved data-* attributes. Roles, ARIA, refs, handlers, state attributes, and owned geometry remain component-owned. Existing content props and children remain the content slots.

Best practices

Keep `order` the single source of row order; update it when a message arrives and the row glides to the top.
Don't re-key rows to reorder them; that remounts them and loses focus.

Tokens

The stylesheet reads these tokens, so a theme restyles the component without overrides.
