CommentThread

Tree manager for comments: nested lists, a depth cap, per-branch "view more replies" with a reveal animation, rendering every comment through the host.

Usage

Use the import, not the markup. Copy this line into your code; never paste the preview HTML below.

import { buildCommentTree, countDescendants, visibleReplies, flattenReplies, moreRepliesLabel, CommentThread } from 'cieo/CommentThread';

Guide

Use when

  • Comment sections with nested replies.
  • Any tree of posts where branches can be long.

Avoid when

  • Flat chats; use ChatMessageList.

Anatomy

A section holding nested ul role="list" branches. Each li holds whatever renderItem returns; hidden replies sit behind a "View N more replies" button at the end of the branch.

Behavior

  • buildCommentTree keeps input order, turns orphans into roots and breaks cycles; countDescendants, visibleReplies and flattenReplies are pure.
  • Each branch shows initialReplies until its button is pressed; the revealed replies open on a height animation, neighbours slide (FLIP), and focus moves to the first new reply.
  • maxDepth is capped at 32. Past that depth, descendants are listed in order at the cap. Expanded ids are internal unless expanded and onExpandedChange are passed.

Keyboard / accessibility

Real nested lists with optional per-branch labels. The reveal is a real button; the animation is skipped for reduced motion.

Do / don't

  • Do: pass branchLabel so each list has a name.
  • Do not: change keys between renders; row identity drives the slide.

Customization

Spacing comes from Comment; the more button uses control tokens.

Limitations

  • No collapse-again control; hosts can reset expanded.
  • Hidden counts are direct replies of the branch.

Related

Comment, CommentComposer, SortableList.

Host customization

className adds a class to the root without replacing the Cieo class. slotProps accepts named presentation parts: root, branch, list, item, more. Each part accepts className, style, title, and nonreserved data-* attributes. Roles, ARIA, refs, handlers, state attributes, and owned geometry remain component-owned. Existing content props and children remain the content slots.

Best practices

Build the tree with `buildCommentTree` so orphans and cycles are handled for you.
Don't render nested lists yourself; the thread owns list semantics and the reveal.
