Library/Molecule

Field

Label plus one control plus a help or error row (every labeled input, select, or custom control).

Usage

import { Field } from 'cieo/Field';

Use your work email

<Field label="Email" htmlFor="email" description="Use your work email">
  <input id="email" type="email" />
</Field>
npx cieo add Field
/* Root selector: .cieo-field (named-slots) */
import Cieo

// Shared Cieo tokens & Motion.snap spring counterpart for Field

  .environment(\.cieoTheme, .instrument)

Anatomy

State machine

Interactive fieldValidation state transitions and TransitionEnvelope output from cieo/state.

Properties

NameTypeDefaultDescription
labelstring—Visible label bound to the control.
htmlForstring—Id of the wrapped control for label focus.
descriptionstring—Help text shown when there is no error.
errorstring—Validation message; wins over description.
classNamestring—Appended to the root classes without replacing library classes.
slotPropsobject—Typed presentation record; see TypeScript declaration. Named parts: root, label, help.

Guide

Use when

  • Every labeled control: wrap the control so label, input, and help text stay in one grid stack.
  • The control needs help text (description) or a validation message (error).

Avoid when

  • The control has no visible label; give it one instead of skipping Field.
  • You need grouped choice semantics; that is a radio, checkbox group, or segmented control, not a Field.

Anatomy

Root .cieo-p-field grid: <label>, host control child, then one .cieo-p-help paragraph. The host supplies the control with a matching id for htmlFor.

Behavior

Error wins over description: only one help row renders. The help id derives from htmlFor (-error / -help suffix); no htmlFor means no help id.

Keyboard / accessibility

  • label is required. Pass htmlFor matching the control's id so label focus works.
  • Error renders with role="alert" so assistive tech announces it; it replaces (never stacks with) the description.

Do / don't

  • Do: <Field label="Email" htmlFor="email" error={err}> with <input id="email"> as child.
  • Don't: render both description and error; pass error and let it win.

Customization

None per instance. Gap, label weight/size, and help tone colors come from Cieo tokens; error tone is danger.

Limitations

  • Exactly one child control (default slot min 1, max 1). More means the controls need separate Fields.
  • No label-position variants; label always sits above the control.

Related

Slider (atom), Range (control), ButtonGroup (molecule).

Host customization

className appends a root class. slotProps exposes root, label, help. Each part accepts className, style, title, and non-reserved data-* attributes. Existing content props and children remain the composition slots. Library classes are retained; computed inline geometry, state attributes, handlers, refs, roles, and accessibility attributes remain owned by Cieo.

Best practices

Wrap every labeled control so label, input, and help text stay in one stack.
Don't render both description and error; pass error and let it win.
