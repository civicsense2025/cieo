AlertDialog

Dialog wrapper that marks urgent content with alertdialog semantics (delete a conversation, discard work).

Usage

Use the import, not the markup. Copy this line into your code; never paste the preview HTML below.

import { AlertDialog } from 'cieo/AlertDialog';

Delete conversation?

This removes all 42 messages. You can't undo this.

<AlertDialog label="Delete conversation" open onClose={close}>
  <h2>Delete conversation?</h2>
  <p>This removes all 42 messages. You can't undo this.</p>
  <p><button>Delete</button> <button>Cancel</button></p>
</AlertDialog>

Properties

NameTypeDefaultDescription
labelstring—Accessible name for the alert. Required.
openboolean—Whether the alert is open. Renders null when false or omitted.
onClosefunction—Called on Escape or host close affordances.
classNamestring—See TypeScript declaration for the named presentation or content slot contract.
slotPropsobject—See TypeScript declaration for the named presentation or content slot contract.

Guide

Use when

  • The user is about to destroy data or take an irreversible step.
  • The message needs alert semantics so assistive tech announces it immediately.

Avoid when

  • The outcome is reversible or low-stakes; use Dialog instead.
  • You need a passive notice; that is a banner or toast, not a modal.

Anatomy

Same-lane Dialog shell (scrim, centered panel, Escape) with an inner role="alertdialog" region carrying the label.

Behavior

No motion. Renders null when open is false or omitted; the host owns open state. No extra visuals of its own.

Keyboard / accessibility

  • Inner region carries role="alertdialog" plus the label; the outer dialog keeps the same name.
  • Escape invokes onClose. Focus management belongs to the host, as with Dialog.

Do / don't

  • Do: <AlertDialog label="Delete conversation" open onClose={close}> with Delete/Cancel actions.
  • Don't: use it for routine confirms; alert semantics lose force when overused.

Customization

None. AlertDialog has no style parts of its own; it reuses Dialog visuals exactly.

Limitations

  • No focus trap or restore; the host wires those around this shell.
  • One content subtree (slot max 1). Destructive wording belongs to the host copy.

Related

Dialog (organism), DialogHeader (molecule), BottomSheet (organism).

Host customization

className adds a class to the root without replacing the Cieo class. slotProps accepts named presentation parts: root, content. Each part accepts className, style, title, and nonreserved data-* attributes. Roles, ARIA, refs, handlers, state attributes, and owned geometry remain component-owned. Existing content props and children remain the content slots.

Best practices

Reserve alert semantics for irreversible steps like deletion.
Don't use AlertDialog for routine confirms; overuse dulls its urgency.
