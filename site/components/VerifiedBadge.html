VerifiedBadge

A small seal with a check that marks an account as verified, named for screen readers and tinted by the accent color.

Usage

Use the import, not the markup. Copy this line into your code; never paste the preview HTML below.

import { verifiedBadgeSize, VerifiedBadge } from 'cieo/VerifiedBadge';
<VerifiedBadge />
<VerifiedBadge size="sm" label="Verified account" />

Properties

NameTypeDefaultDescription
labelstringVerifiedAccessible name read by screen readers.
size'sm' | 'md'mdsm sits inline with caption text, md with body text.
classNamestring—Additional root CSS class. Built-in classes remain.
slotPropsobject—Typed presentation parts: root, seal, check. Accepts className, style, title and non-reserved data attributes; owned semantics and dynamic styles remain.

Guide

Use when

  • Next to a display name whose account the host has verified.

Avoid when

  • Marking anything that is not a verification (new, staff picks); use Badge.

Anatomy

One inline svg with role="img" and an aria-label, a filled seal and a check stroke.

Behavior

  • size="sm" sits inline with caption text, md (default) with body text. Unknown sizes fall back to md.
  • No motion.

Keyboard / accessibility

Not focusable. Screen readers read the label ("Verified") after the name.

Do / don't

  • Do: pass a translated label in non-English interfaces.
  • Don't: show it without the host having verified the account.

Customization

Use the typed presentation parts listed under Host customization. Defaults still use Cieo tokens; component behavior and accessibility remain owned by Cieo.

Limitations

  • One seal shape; it does not carry verification kinds or dates.

Related

Badge, Avatar, Mention.

Host customization

className adds a root class without replacing Cieo’s classes. slotProps exposes root, seal, check. Each part accepts className, style, title, and non-reserved data-* attributes. Roles, accessible names, values, event handlers, refs, state markers, and dynamic geometry remain component-owned. Existing content props retain their original semantics.

Best practices

Place it right after the display name so the name and badge read as one phrase.
Don't use it as a decorative checkmark; it asserts that the account was verified.

Tokens

The stylesheet reads these tokens, so a theme restyles the component without overrides.
